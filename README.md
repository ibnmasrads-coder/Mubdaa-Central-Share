# Mubdaa Central Share

Independent WordPress companion plugin for **MainWP Dashboard**, focused on desktop WhatsApp sharing immediately after publishing.

## Requirements
- WordPress 6.3+ and MainWP Dashboard installed on the **central dashboard only**.
- Desktop browsers: Chromium-based browser with image clipboard capability recommended.
- No WhatsApp API, WhatsApp Web automation, or changes to MainWP/Bridge files.

## UX contract
- Publishing completes normally; selected successful links are gathered from MainWP results.
- A lightweight share workspace appears above the native MainWP posting modal **after the final child-site result**.
- The source article image is fetched via an authenticated, same-origin WordPress endpoint; title is rendered on the PNG above the original photo. A failed fetch reports the exact HTTP status and offers retry.
- Sharing happens manually: paste the image into WhatsApp Web/Desktop **first**, then click **Copy all links** once; there is no splitting or truncation. If WhatsApp's image-caption limit is exceeded, paste the entire text as a subsequent text message (still one copy/paste).
- No permanent share history. One short-lived transient can hold source image metadata across MainWP's temporary-post deletion.
- Never claim WhatsApp messages were sent; the operator must confirm in WhatsApp.

## Project state
Development baseline. **Do not deploy to a live client dashboard until integration QA on the exact MainWP release**.

## v0.2.0-dev hotfix

- Fixed a critical source-image bug: `sanitize_key()` lowercased the mixed-case batch token generated by `wp_generate_password()`, invalidating the nonce and ephemeral image lookup.
- The browser fetches the source image using the same-origin, authenticated AJAX endpoint and shows diagnostic HTTP errors.
- The image proxy follows a limited number of WordPress-safe HTTP redirects.
- One-click clipboard text includes **every** selected site link regardless of character count.
- Removed the `(2/4)` split-caption button. The one-field preview is complete.
- Image retry is available after an HTTP/source failure.
- Added functional PHP image endpoint and ten-site long-message regression tests.

The real client image still needs confirmation on the live MainWP instance. The plugin has **not** been deployed and no existing MainWP/Bridge code is touched.


## v0.3.0-dev — Verified shortlinks and document exports

The original copy PNG / download PNG / copy full text workflow remains available. New independent buttons download **PDF** and **Word (.docx)**.

- MainWP's successful child post IDs are captured via \`mainwp_bulkposting_done\` while the original MainWP publishing flow is unchanged.
- Each link is generated from that particular site's confirmed remote post ID: \`https://site.example/?p=123\`. Existing pretty permalinks are never changed. If confirmation is unavailable, the plugin retains the original published URL rather than guessing a new ID.
- The share caption contains only URLs, one per line, with no site names.
- PDF uses the existing headline+image card and **selectable live text hyperlinks** with clickable PDF annotations; links may span multiple pages.
- Word uses an editable Arabic headline, the original featured photo and native Word clickable hyperlinks.
- Both exports are produced locally in the operator's browser from a bundled copy of pdf-lib and JSZip; the plugin does not send material to third parties.
- Downloaded files can be attached to WhatsApp Web/Desktop as **Documents** via the attachment UI or drag-and-drop. Pasting an entire PDF/DOCX file using Ctrl+V is not reliably supported by WhatsApp and is not promised.
- No persistent share history; child ID mapping is stored only in short-lived, user-scoped WordPress transients.
- Desktop only; WhatsApp API automation is not used.

## Manual acceptance steps

1. Publish a new article with a featured image to at least two sites and confirm the share panel still opens immediately.
2. Wait for short URLs to appear, check they resolve to **the right article** on every child site, and confirm the selected URL list is a single, one-click copy.
3. Copy PNG and paste into WhatsApp Web/Desktop; send full text as a media caption when short enough, otherwise as one subsequent text message.
4. Download PDF and DOCX, open both on Windows, click and copy several links (first, middle, last); verify the picture/title are correct.
5. Test one failed child-site publish: it must not enter the share link list.
6. Test a publication with no image: document export should remain disabled, normal publication unaffected.

The GitHub CI exercises 30 external links and validates real PDF clickable annotations and DOCX hyperlink relationships. **Live WhatsApp / MainWP deployment QA remains required before production approval**.

## v0.4.0-dev — Ambiguous publish readback and optional caption controls

- A child-site 503 or missing MainWP acknowledgement is **not** treated as proof that publication failed. Following the last bulk result, the sharing screen automatically queries each failed child **through MainWP's existing authenticated read-only `get_all_posts` call**, one site at a time. It never retries the publishing operation.
- An apparently failed site is added only if exactly one published post has the **exact same title** and a publication timestamp close to this sharing session. The child-supplied ID is used for `?p=`. Missing, ambiguous, expired, or unreachable results are **excluded and visibly flagged** for a manual recheck. This is a cautious recovery heuristic, not a guaranteed cross-site transaction receipt: duplicate articles or posts older than the session window may need human verification.
- An image missing on the recovered child post does **not** suppress its verified published link. A recovered link is marked so the editor knows the featured image may still require repair.
- Optional **remove `www.`** is initially unchecked and applied only when explicitly selected. The customer must verify that non-www domains resolve; this does not change WordPress canonical URLs or permanent redirects.
- Optional **split WhatsApp caption** is initially unchecked. Selecting it reveals 2/3/4 groups with balanced, ordered per-group preview and independent copy buttons. The original full-caption copy action remains available; no URLs are truncated. Groups might still exceed WhatsApp's caption allowance if an individual URL is very long.
- PDF and Word remain independent of WhatsApp text limits, export the complete selected link list, and do **not** split documents into WhatsApp groups. The selected `www.` display setting does affect exported links as a convenience; the original URLs are always retained in memory.
- Uses an admin-only nonce-scoped 30-minute transient for the publication title/time; no persistent history and no child-site plugin edits.
- Staging/QA only until integration tested on the actual MainWP version and site network.
